# Decision gates

Content that depends on an unconfirmed decision or assumption gets rewritten. Ask first.

- Split the work into sections. Send one section with its questions in each reply.
- Give each question an id (`A1`, `B2`…), lettered options with consequences, and a
  recommendation.
- End the reply with the status of the section (closed or open) and the next step. Then wait.
- Deliver content that needs no decision without a stop.
- If the decisions are few and cheap to reverse, skip the gate: take the actions and continue.
  Never skip the gate for a design choice or a security choice.
- At the top of each reply, under the heading "Actions taken", list each action that you took
  without input from the user: skipped gates, assumptions, questions that you answered. Write
  one line each, with no reasons and no options. Do not list the user decisions.
- In a run with no user to ask, this rule does not apply.
